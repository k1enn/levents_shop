Phoneshop on AWS

Replaces the Cloudflare Workers plan. Region ap-southeast-1 (Singapore). DB: DynamoDB. IaC: Terraform, disposable app stack: make up creates and seeds everything, make down deletes it. Target cost about 0 USD per month. Research run wf_cb762a0c-17a, 2026-11-23. Migration plan: plans/261123-aws-dynamodb/plan.md.

Up and down

make up     # npm run build, terraform apply, seed runs if the table is new
make down   # terraform destroy, nothing left but infra/bootstrap
  • infra/bootstrap is applied once: state bucket, GitHub OIDC role, budgets. Never destroyed.
  • infra/app holds the whole shop. Every make up from empty gives a seeded shop: phones, 2 coupons, admin user, product images.
  • Orders and users made while up are lost on down. That is the point of disposable.
  • Each full apply gives a new *.cloudfront.net URL, printed as output. Terraform writes it to SSM /phoneshop/APP_URL, the app reads it at cold start. This breaks the cycle CloudFront needs Lambda, Lambda needs the CloudFront URL.
  • CloudFront create and delete take several minutes each not verified.

Terraform layout

infra/
  bootstrap/main.tf   state bucket, OIDC provider + role, budgets
  app/main.tf         backend "s3" { use_lockfile = true }
  app/data.tf         DynamoDB table, S3 bucket, aws_s3_object seed images
  app/lambda.tf       archive_file build, Lambda, Function URL, IAM, log group
  app/cdn.tf          CloudFront, OAC, origin header, cache policies
  app/config.tf       random_password, SSM params, APP_URL param
  app/seed.tf         terraform_data local-exec node seed.mjs
  app/outputs.tf      url, table, bucket
Makefile
  • Seed: terraform_data with triggers_replace = aws_dynamodb_table.main.arn, so it seeds again only when the table is new. The script is idempotent, rerun is safe.
  • Seed images: aws_s3_object with for_each = fileset(...) and etag = filemd5(...).
  • Secrets: random_password for session and origin secret. MoMo and VNPay keys come from TF_VAR_* (local env or GitHub secrets), never from a tfvars file in git.
  • State holds those secrets in plain text. The state bucket is private, encrypted, versioned.

Request flow

  • User hits the *.cloudfront.net URL over HTTPS with the default CloudFront cert.
  • /assets/* and /images/* go to S3 via OAC. Bucket stays private. Long TTL, hashed file names.
  • Everything else goes to Lambda SSR. Catalog pages with public Cache-Control get cached at the edge. Cart, checkout, account, admin and IPN routes are never cached.
  • CloudFront adds a secret header. The app returns 403 without it, so the Function URL cannot be hit directly.
  • MoMo and VNPay call the IPN routes through CloudFront too.
  • Lambda reads SSM params at cold start. It talks to DynamoDB with its IAM role: no DB password, no open allowlist.
  • Catalog list, search and filters run on all products in Lambda memory (60 s TTL). Cart and checkout read fresh stock with BatchGetItem.
  • Rate limit: counter items in DynamoDB per name + IP + minute, deleted by TTL. Replaces the Workers limiter.

Decisions

  • Compute: Lambda, no VPC, classic Function URL. high Lambda Web Functions (Oct 2026) run the Node server as is, but bill memory for the whole life of each environment, idle time included. 3rd party tests show about 2.65x cost for sporadic traffic. A demo stack is sporadic, so the classic Function URL with the Lambda Web Adapter wins.
  • CDN: CloudFront pay as you go, no custom domain. your choice The Free flat rate plan is attached per distribution and Route 53 zones break the domain when destroyed, so both do not fit a disposable stack. At demo traffic pay as you go stays in the always free tier not verified.
  • No WAF. Without the flat rate plan a web ACL costs about 5 USD + 1 USD per rule per month not verified. The app limiter in DynamoDB does the job.
  • DB: DynamoDB single table, on demand. not verified IAM auth, no password, no connection handling, same region. Search has no regex, so the catalog is filtered in memory. No PITR or deletion protection: the seed is the backup.
  • Secrets: SSM Parameter Store Standard. not verified Free. Secrets Manager is about 0.40 USD per secret per month.
  • IaC: Terraform, S3 backend with native lock. your choice use_lockfile = true (Terraform 1.10+), no DynamoDB lock table.
  • CI: GitHub Actions with OIDC. not verified 2 manual workflows, up and down. No long lived keys. Trust policy scoped to repo and branch via the sub claim.

DynamoDB data model

  • Product: PK PRODUCT, SK id. Variants as a map keyed by SKU, so stock drops with 1 conditional update.
  • User: PK USER, SK id. Email lock: PK EMAIL#<email> keeps email unique.
  • Order: PK ORDER#<code>. GSI1 USER#<id> + createdAt for my orders. GSI2 ORDER + createdAt for admin.
  • IMEI lock: PK IMEI#<imei> holds the order code. 1 IMEI in at most 1 order, warranty lookup is 1 GetItem.
  • Review: PK REVIEW#<productId>, SK userId, so 1 review per user. Product keeps ratingSum + numReviews.
  • Coupon: PK COUPON, SK code. Lead: PK LEAD, SK createdAt#id.
  • Rate counter: PK RATE#<name>#<ip>, SK minute, ADD n, ttl now + 120 s.
  • Trap: 1 TransactWriteItems cannot touch the same item twice. 2 SKUs of 1 phone in 1 cart must be 1 update. Max 100 items, 2x capacity cost.

Lambda origin: the trap that breaks POST

  • OAC in front of a classic Function URL needs AWS_IAM, and every POST must carry x-amz-content-sha256. Browser form actions and MoMo/VNPay IPN never send it, so they fail with InvalidSignatureException.
  • Fix used here: Function URL with AuthType NONE. CloudFront adds a secret custom origin header (random_password, new each apply). The app returns 403 when the header is missing or wrong.
  • Web Function option: IamAuth, OAC origin type lambda, origin request policy AllViewerExceptHostHeader. CloudFront signs POST with UNSIGNED PAYLOAD, so forms and IPN work.
  • If u use OAC on a Function URL anyway: since Oct 2025 grant both lambda:InvokeFunctionUrl and lambda:InvokeFunction to cloudfront.amazonaws.com with the distribution SourceArn, or u get 403.

Cost estimate per month

  • While down: state bucket only, about 0 USD. First 2 budgets are free not verified.
  • While up, CloudFront: 0 USD inside the always free tier not verified
  • Lambda: 0 USD inside free tier (1M requests, 400k GB seconds)
  • S3: cents for a few MB of assets and images
  • DynamoDB on demand: cents at demo traffic, 25 GB storage free not verified
  • SSM Standard, CloudWatch with 7 day retention: about 0 USD
  • No domain, no Route 53, no WAF: 0 USD

Cost traps

  • NAT Gateway: about 32 USD/month plus data. Do not put Lambda in a VPC.
  • ECS Express Mode / Fargate: always on ALB about 16 USD/month. App Runner: closed to new customers since Apr 30, 2026.
  • Public IPv4: every public IPv4 address bills hourly. No EC2, no Elastic IP.
  • Orphan log group: if Lambda creates its own log group, it is not in state and survives destroy. Create it in Terraform.
  • S3 bucket with objects blocks destroy unless force_destroy = true.
  • CloudWatch Logs default retention is forever. Set 7 days.
  • Cache miss flood with no WAF: Lambda and DynamoDB bill per request. Cache catalog pages hard, keep the app limiter on auth and checkout. Run make down when not demoing.

Code changes vs the Cloudflare plan

  • wrangler.jsonc, workers/app.ts, @cloudflare/vite-plugin: replace with the Node server build of React Router.
  • cloudflare:workers env: replace with 1 env.server.ts that loads SSM params at cold start.
  • mongodb driver, withDb, withTx: replace with DynamoDB DocumentClient, conditional updates and TransactWriteItems.
  • R2 binding IMAGES + images/* route: replace with S3 PutObject. CloudFront serves /images/*.
  • Rate limiter binding LIMITER: replace with DynamoDB counters.
  • Cache tag purge: replace with CloudFront CreateInvalidation. Keep the public Cache-Control headers.
  • CF-Connecting-IP: replace with CloudFront-Viewer-Address.
  • seed.mjs: write to DynamoDB, run by Terraform.
  • PBKDF2 low iteration count was a Workers CPU workaround. Raise it.
